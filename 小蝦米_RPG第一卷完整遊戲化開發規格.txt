《小蝦米：異世英雄傳》第一卷《清河村風雲》
RPG 遊戲化開發規格書 / 供 Claude Code 參考
版本：V1.0（需求規劃，非既有功能完成聲明）
技術偏好：Vue 3 + Vite + Pinia + Phaser + JavaScript（禁止 TypeScript）
文案語言：繁體中文；古風角色中文配音日後以中國大陸普通話為方向。

【本文件定位】
本檔是把「28章劇情與人物對話.txt」轉換成可開發的 RPG 功能與任務需求，不取代小說。請先閱讀專案現有程式碼、資產目錄與 README，盤點已完成的地圖、人物、素材、場景、UI、戰鬥與存檔，不得假設專案是空白。所有數值僅為暫定平衡值，需由實際試玩調整。優先垂直切片，避免一次製作28章或重寫既有系統。

一、遊戲定位與體驗
遊戲類型：2D 像素風武俠穿越 RPG；重視探索、對話抉擇、有限資源下的村莊建設、隊伍培養與回合制戰棋。靈感方向：經典開放式江湖探索、戰棋 RPG 的地形與站位、三國志式的補給與軍事決策，但不複製任何第三方的受保護素材或程式。
核心體驗循環：探索地圖 -> 發現 NPC/線索/事件 -> 對話與選擇 -> 採集、交易、交涉或戰棋 -> 得到資源、信任、情報 -> 改變村莊和人物關係 -> 開啟新區域與章節。
原則：劇情與玩法互相影響；玩家的善意需要支付時間和糧食；不是每一次衝突都要靠戰鬥解決；失敗不一定遊戲結束，可導致成本、支線關閉或後續負面效果。

二、不可修改的故事設定（CANON）
世界：架空「大雍」末世，戰亂、苛稅、飢荒、官匪勾結。
清河村：初始86名村民，缺糧，舊王宅為主角據點；村民不會因一場勝仗立刻致富。
主角：小蝦米/王小明，26歲，180公分，現代臺灣工程師，銅橘色刺短髮；初登場紅帽T，換裝後藍色武俠服與紅圍巾；初期不會高深武功，靠觀察、戰術與同伴補足。
沈若蘭：23歲，藥師，尋找失蹤父親沈懷仁。
秦無風：26歲，冷面高機動劍客；第1章可有不露面的聲音伏筆，第4章正式登場，第15章月下共飲是核心羈絆事件；與秦紅櫻同姓但無血緣關係。
顧文淵：27歲，謀士，曾與蘇映雪訂婚；第3章登場。
黑風寨：秦紅櫻（大當家）、陸玄策（二當家，謀士）、鐵震山（三當家，猛將）。為秦嵐冤案受害舊部，紀律嚴明，不隨意掠奪平民；糧食短缺。
清風寨：武松率領約65名難民，老弱婦孺占多數；武器「伏虎鐵棍」。百兩過路費和三分支是固定主線支線設定。
突風寨：雷萬山（大當家）、石虎（二當家），為殘暴掠奪勢力，與青石縣主簿杜文昌勾結；第一卷主要敵人。石虎絕不能配置成黑風寨成員。
核心冤案：三年前秦嵐因北境軍餉軍糧案被誣陷入獄；沈懷仁失蹤、秦無風師父遇害、黑羽衛令牌、青石北倉、蘇記商行等線索互相關聯。第一卷不能揭開全部真相，也不能把蘇記商行印記直接等同定罪蘇映雪。
28章分六篇，目錄與完整場景請讀另一個TXT。

三、七大玩法系統（開發目標）
01 地圖探索：自由行走、碰撞、交互提示、室內外轉場、拾取物、採集點、探索後重訪差異、NPC位置與可用時段。每張地圖至少有一個故事事件、一個可互動點、一個可追蹤的探索回報；非必要不放隨機怪。
02 戰棋戰鬥：回合制方格，移動範圍、行動點/回合規則、攻擊範圍、站位、地形、防禦、技能、狀態、簡單敵方AI、勝敗條件、戰後回寫狀態。先做單場小隊戰，才擴張多目標的大型戰役。
03 村莊經營：糧食/木材/鐵材/銀兩/藥材/人口/可用人力/民心/防禦；建築建造與升級；季節、田作生長週期、耗糧與傷病。不能按下按鈕就無限產糧；收容難民必須增加對應需求。
04 同伴羈絆：信任、情誼、理念認同三種獨立屬性；對話選擇可影響羈絆；角色各自有個人立場、條件與劇情解鎖；親密/知己事件應靠事件而非單純送禮刷數值。
05 三寨勢力：黑風寨好感與合作程度、清風寨安置結果、突風寨威脅度、官府注意度；計入選擇後果、軍事援助、救援支線和結局。
06 武功與裝備：角色能力值、等級/經驗、裝備欄、基礎技能與專屬技能、相互配合的組合技；前期主角不應成為無敵高手。
07 NPC日常與支線：NPC作息/位置/好感觸發、委託、採藥、修繕、交易、簡單生活事件；支線需回饋主線資源或角色變化。

四、六篇章節對應玩法
第1-5章「異世求生」：探索、對話、採集、王宅、背包、救秦無風；第1章提供操作教學，第2章呈現飢餓村莊，第3章修王宅，第4章救援戰，第5章療傷藏匿與推進旗標。
第6-10章「糧荒與惡匪」：初步資源管理、探子辨識、官差徵糧、石虎勒索、村民議事、三日通牒。
第11-15章「清河村保衛戰」：勞動人口分配、民兵、地圖防禦、警戒和撤離、石虎前哨戰、大型村莊防守戰、戰後修復與第15章月下共飲CG事件。
第16-19章「將門紅櫻」：黑風寨地圖、外交、秦紅櫻/陸玄策/鐵震山專屬對話、帳冊情報驗證與有限聯盟。
第20-23章「清風寨的百兩賭約」：武松收取100兩、三條選項、伏虎鐵棍、清風寨難民需求、安置及招募條件。
第24-28章「三寨風雲」：青石北倉調查、三寨會盟、突風寨回擊、大型多目標戰棋、戰後恢復與三類結局，結尾引出蘇映雪和第二卷。

五、武松事件不可違反的三條分支
A 付100兩：武松帶錢回清風寨購糧，主角放行；武松暫不招募，支線關閉或弱化，可能不再出現。
B 武力勝利：需由合理戰力或隊伍擊敗武松；獲得「伏虎鐵棍」；武松退走，不能當場招募。若故事需要武松日後回歸必須新增合理的和解事件，不可無條件歸隊。
C 提議賭約：武松勝，主角付100兩；武松敗，武松付50兩；勝負遵循事前協議的公平規則。事件後承諾拜訪清風寨；開啟難民安置支線。成功安置、糧食/住屋/醫療足夠、村民和難民同意，才有武松加入可能。當下不能自動入隊。
資源規則：100兩/50兩是高額資源，玩家需擁有來源或明確擔保；清河村公共口糧不可被玩家任意挪用。處理資金不足的方式應是提示條件不足、提供非強迫的替代劇情，而不是免費提供金錢。
武器：武松使用伏虎鐵棍（可配技能伏虎三擊/破防/擊退），不改為戒刀或空手主武器。

六、清河村模擬設計
示範初始：人口86、公倉口糧可供約5日（不等於所有家庭5日後斷糧）、民心35/100、木材30、鐵材8、防禦12/100。這些是未驗證的「可調平衡值」，設置於數據檔而非硬編碼。
建築：王宅（據點/存檔/羈絆）、水井（飲水/衛生）、糧倉（減損）、農田（季節性收成）、鐵匠鋪（修造）、醫舍（治療）、民兵訓練場（防衛）、難民住屋（人口容量）。可使用階段、等級與前置資源。
勞動者範例：可調度15人，農作採集/伐木/修繕三分類；每一名勞動者每回合只能分配一個工作；總指派不得超過可用數；資源不得小於0；產出和消耗要有清晰日誌。
示範公式：當日食物獲得量 = 採集勞動者 * 2（需受資源點枯竭限制），木材 = 伐木勞動者 * 3，修繕點 = 修繕勞動者 * 2；正式農作應播種、等待成長、收穫，不能每日採收成熟田作。每日糧耗依人口/配給/健康計算，難民加入後糧耗增加，建築消耗材料、勞動和時間。
每次重大選擇至少更新：gameFlags、資源、NPC態度、日誌和任務狀態中的相關欄位；不得只修改顯示文字。

七、角色戰鬥設計
小蝦米：戰術支援/初階劍士，戰場觀察、臨機應變；突出指揮不靠暴力碾壓。
秦無風：高機動劍士，無風一閃、破綻追擊。
沈若蘭：醫療，止血、急救、藥物調配；治癒消耗藥材或次數。
顧文淵：軍師/控制，識破敵計、鼓舞、調度。
秦紅櫻：槍將/指揮，紅纓突刺、軍令整隊。
鐵震山：重裝前鋒，破陣重擊。
武松：棍術破防/擊退，伏虎三擊、橫掃千軍。
組合技：小蝦米+秦無風「生死相託」（信任/事件達標才解鎖）；武松+秦紅櫻「破陣伏虎」（兩者實際在場且配合條件成立）。這些技能名稱屬暫定遊戲設計，可調整平衡，不要隨意更改角色性格。
戰場地形：森林、泥地、河岸、木橋、村門、屋舍；不同類型影響移動成本/掩護/射程與技能。初期先實作3種地形差異與2種戰場勝利條件。
兩場大型戰役：第14章村莊保衛戰、第27章突風寨決戰；中小戰至少包含第4章救秦無風、第13章敵人試探，以及第21章武松比試（視選擇）。

八、角色羈絆與對話
每一個角色至少有 trust/affection/ideology 三個量化指標，0-100僅供初始方案；劇情條件另外用旗標，不可只判斷分數。
秦無風事件：第5章「傷者的戒心」、第12章「木劍之約」、第15章「月下共飲」、第19章後「故人遺物」、第27章「生死相託」。第15章核心對話：秦無風「信錯人，會死。」小蝦米「不信任何人，難道就不會死？」玩家可選擇知己情誼或含蓄曖昧的回應，不強制戀愛路線。
對話格式要支援：speaker、portrait、text、mood、voice（可缺省）、cg（可缺省）、choices、conditions、effects、next、eventId、已讀旗標、任務連結。台詞繁體中文，配音檔未確認時不得使用無效引用或卡住劇情。

九、必備地圖與重訪變化
清河村：村口、王宅、水井、醫舍、鐵匠鋪、糧倉、農田、村民民宅。需能看到村莊從貧困到修復的變化。
黑松林：採藥、野獸、山路、秦無風救援，後期可再訪取得情報。
黑風寨：寨門、軍帳、練兵場、情報處、倉庫；軍紀有制度。
清風寨：難民屋棚、食物分配點、醫療點、武松事件；安置程度有視覺反饋。
突風寨：外哨、主寨、倉庫、囚牢、多入口；最後決戰。
輔助：王宅室內、清風山道、青石北倉、戰棋獨立關卡。
可使用既有 tileset，未完成美術用標示清楚的占位素材；不得誤稱占位圖是正式美術。

十、技術架構與資料界線
沿用現有 Vue3/Vite/Pinia/Phaser JavaScript 專案及既有路由、資產管理和 UI；若部分技術未安裝，先確認原因與依賴衝突。
Vue：對話 UI、任務日誌、背包、村莊人力、角色面板、建築與戰鬥 HUD。
Phaser：地圖呈現、角色走動/碰撞、交互判定、戰棋畫面、動畫、特效。
Pinia：單一真實狀態來源 game/party/inventory/village/quest/relationships/factions。Phaser 不要私自維持會與 Pinia 永久衝突的第二份劇情狀態。
Data-driven：chapters、dialogues、quests、characters、items、skills、buildings、maps、encounters 應由 JavaScript object 或 JSON 描述並可驗證。資料與 UI 分離，後續新增章節不必複製整套 Scene。
事件：採穩定 eventId、questId、chapterId、choiceId、characterId；任務/存檔只依賴 ID，不依賴 UI 中文名稱。避免透過 eval 執行條件。條件與效果使用受控操作類型，由程式顯式解析。
存檔：最少3格、版本號、時間、章節、位置、隊伍、inventory、resources、flags、quest statuses、relationship values、faction values、已領獎勵ID、建築階段；提供 migration 或不兼容的明確提示；需要防重複獎勵。

十一、28章事件/任務拆法
01 穿越教學：移動、觀察、互動、背包、前往求救聲。
02 林道救沈若蘭：用掩護/環境拖延，見老吳，進清河村，認識糧荒。
03 修王宅：蒐集有限木材、借工具、改善排水、認識顧文淵和韓鐵山。
04 救秦無風：森林追兵救援戰/撤退、受傷狀態、取得黑羽令線索。
05 療傷藏匿：藥材、村長協商、王宅警戒、軍糧殘信。
06 黑羽探子：辨識偽裝商販、謊報測試與警戒；找出縣衙通行證。
07 缺糧議事：公開公倉、官差徵糧、核帳、短期口糧方案。
08 石虎勒索：首次敵方交涉、資源/聲望/恐懼狀態、三日通牒。
09 村民投票：建議逃難、繳糧或抵抗，安排避難與居民分工。
10 倒數備戰：地形偵察、安排守點、敵方提前行動。
11 勞動管理：伐木、修柵欄、食物採集、醫療和補給分工。
12 民兵訓練：秦無風木劍、基本戰棋教學深化、布防。
13 前哨突襲：守護老吳、村民被威脅支線，決定處置方式。
14 清河村保衛戰：村門-側翼-核心三階段戰棋，損失回寫。
15 戰後修復：情緒對話、月下共飲、軍糧與黑風寨標記。
16 山道交涉：黑風寨哨兵、鐵震山攔阻、秦紅櫻初登場。
17 黑風寨調查：秦嵐冤案、軍紀與糧荒、與秦紅櫻爭辯。
18 陸玄策考驗：情報整理、護送補給設計，非單純答對謎題。
19 有限盟約：黑風寨與秦無風互相疑慮，建立有限軍事合作。
20 清風山路：武松伏虎鐵棍堵路，100兩要求。
21 百兩賭約：A付錢 / B武力奪棍 / C雙向賭約；永久記錄選擇。
22 難民調查：清風寨65人需求、醫療、食物、村民協商（C路線完整開啟）。
23 難民安置：住房與供給檢查，成功後有機會招募武松。
24 青石北倉：秘密偵察、救囚犯或保全情報的取捨。
25 三寨會盟：黑風寨/清風寨狀態決定可動用援軍與口徑。
26 戰前調度：保衛村莊/精銳出擊/救難民之間分配兵力。
27 突風寨決戰：解救俘虜、保全帳冊、追石虎/雷萬山，多目標戰棋。
28 春天結局：回寫戰後地圖與角色事件；帳冊顯示蘇映雪，第二卷伏筆。

十四、品質與測試
- 所有場景入口/出口可達，碰撞正常，不會穿牆或卡死。
- 同一對話事件若 once=true，重返地圖不能無限重複領銀兩/道具/信任。
- 選擇A/B/C結果在重開遊戲後維持，彼此互斥，不會同時獲得武松與伏虎鐵棍的矛盾結果。
- 遊戲資源與人口不為負；可用人力不得超過現有且具工作能力的人數。
- 角色未入隊不能觸發專屬隊伍技能；死亡/撤退或關卡失敗有合理回復流程。
- 不同決策實際改變至少一項角色/勢力/資源/地圖/任務效果。
- 開發時可開 debug panel 追蹤章節旗標、資源、任務，正式版預設關閉。
- 用 ESLint/測試框架（若專案已有）與 npm run build 驗證。未有測試工具不要未經評估大量增加依賴。
